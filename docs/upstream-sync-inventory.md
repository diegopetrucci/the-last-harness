# Upstream-sync inventory

This contributor-only inventory tracks TLH code that is either copied/adapted from upstream projects or intentionally shimmed against Pi internals. Use it before editing those areas, especially during upstream version bumps.

## Scope and exclusions

Included here:

- active copied/adapted code called out by ticket `tlhm-nkh9`
- Pi-sensitive compatibility shims that patch or mirror upstream behavior

Explicitly excluded here:

- ordinary dependency pins by themselves
- generated runtime `scripts/**/*.mjs` outputs that mirror same-named `scripts/**/*.mts` sources, plus generated same-layout `extensions/**/*.js` outputs that mirror authoritative `extensions/**/*.ts` sources; see [local development](local-development.md) for the generation/freshness workflow

## Review cadence

- **Pi-sensitive items**: re-review on every `@earendil-works/pi-coding-agent` version bump.
- **`annotate-git-diff`**: re-review at least quarterly and on upstream package/repo releases affecting the review UI/flow.

## Pi 0.84.2 review evidence

This inventory was re-reviewed against the Pi `0.84.2` source release published 2026-08-14: the npm package reports git head `914cf1472e715297caa30db4b9535d534a9eb718`, and the [upstream v0.84.2 release](https://github.com/earendil-works/pi/releases/tag/v0.84.2) publishes the matching source archive. The coding-agent, agent-core, pi-ai, and pi-tui `0.84.2` changelogs were read alongside the source diffs from `0.84.1`.

Relevant findings are recorded in the rows below: the fullscreen/managed-tool renderer and model-catalog refresh orchestration changed, but the patched notice hooks, model matcher, selector setter order, settings lock, resource precedence, auth facade, context lifecycle, and thinking-level contracts remain usable. Pi's JSON/RPC `message_update` stream remains delta-only for message content while now retaining cumulative usage; TLH still consumes assistant deltas for live child text and intentionally drops persisted `message_update` records. The AgentSession-backed `pi.sendMessage` path now avoids streaming steering only for `{ triggerTurn: false }`; TLH's omitted-options completion nudge still steers. Pi's fallback renderer now collapses long results for extension tools without a custom `renderResult`: the separately registered child `contact_supervisor` and parent `subagent_supervisor` tools define no custom `renderResult`, so long fallback-rendered output collapses by default but remains expandable and functionally compatible; the `subagent` orchestration tool defines a custom `renderResult`, including for parent management actions such as `resume`, `interrupt`, and `status`, and is unaffected. Pi's custom-system-prompt trailing-newline fix was checked against TLH's packaged `APPEND_SYSTEM.md` composition with no incompatibility. The new lane-based agent session APIs remain unused by TLH.

## Practical sync checklist

1. Reconfirm the relevant upstream snapshot first.
2. Diff tracked sources; for generated runtime outputs, review same-named `scripts/**/*.mts` and authoritative `extensions/**/*.ts` sources rather than their generated `scripts/**/*.mjs` / `extensions/**/*.js` mirrors.
3. Preserve TLH-only safety behavior unless the ticket explicitly says to change it.
4. Run the narrowest targeted tests listed above plus a `git diff --check` pass.
5. If provenance is incomplete, say so explicitly in the PR or ticket notes rather than implying stronger attestation.
