# Upstream-sync inventory

This contributor-only inventory tracks TLH code that is either copied/adapted from upstream projects or intentionally shimmed against Pi internals. Use it before editing those areas, especially during upstream version bumps.

## Scope and exclusions

Included here:

- active copied/adapted code called out by ticket `tlhm-nkh9`
- Pi-sensitive compatibility shims that patch or mirror upstream behavior

Explicitly excluded here:

- ordinary dependency pins by themselves
- generated runtime `scripts/**/*.mjs` outputs that mirror same-named `scripts/**/*.mts` sources, plus generated same-layout `extensions/**/*.js` outputs that mirror authoritative `extensions/**/*.ts` sources; see [local development](local-development.md) for the generation/freshness workflow

## Review cadence

- **Pi-sensitive items**: re-review on every `@earendil-works/pi-coding-agent` version bump.
- **`annotate-git-diff`**: re-review at least quarterly and on upstream package/repo releases affecting the review UI/flow. It is not a Pi-cadence row and is intentionally not restamped by the Pi 0.84.4 review below.

## Practical sync checklist

1. Reconfirm the relevant upstream snapshot and registry metadata first.
2. Diff tracked TypeScript sources; for generated runtime outputs, review same-named `scripts/**/*.mts` and authoritative `extensions/**/*.ts` sources rather than their generated `scripts/**/*.mjs` / `extensions/**/*.js` mirrors.
3. For lifecycle-sensitive rows, verify event ordering and failure/cancellation paths, not only successful output.
4. Preserve TLH-only safety behavior unless the ticket explicitly says to change it.
5. Run the narrowest targeted tests listed above plus a `git diff --check` pass.
6. If provenance is incomplete, say so explicitly in the PR or ticket notes rather than implying stronger attestation.
