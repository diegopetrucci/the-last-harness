# VISION.md

- The core loop: architect > developers + reviewers is non-negotionable. TLH will always prefer the user to spend time on planning/research/understanding rather than micromanaging how work gets done, and reviewed.
- Persistent memory is essential as it lets TLH self-improve and avoid revisting settled decisions.
- Every single extension, prompt, config in TLH must earn its place, while TLH itself should still be extensible, like Pi.
- Users should know how core concepts in agents/harnesses work, eg context, but they should not be managing them explicitly.
